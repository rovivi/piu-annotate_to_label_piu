Causal Mask — La Clave Anti-Leakage

Attention Matrix (posición → posición)
■ Puede atender ■ Self (diagonal) ■ Bloqueado

¿Por qué es crítica la causal mask?

En PIU, el prev_limb del arrow i = label del arrow i-1. Sin causal mask, con teacher-forcing bidireccional, el token i puede atender al token i+1 cuya feature prev_limb ya revela el label del token i.

Ejemplo de leakage: Arrow 5 quiere predecir si fue pie izquierdo (L) o derecho (R). Sin mask causal, puede ver que arrow 6 tiene prev_limb=[0,1,0,0] (L), lo que revela directamente que arrow 5 = L. Eso es trampa.

La causal mask (upper-triangular = -∞) garantiza que la posición i solo puede atender a las posiciones 0..i, haciendo el problema honesto.

Both-Mirror Augmentation

En cada época, el modelo entrena con dos versiones de cada chart:

  • Chart original: flechas en posición normal, labels originales (L/R/E)
  • Chart espejado: flechas reflejadas horizontalmente, labels invertidos (L↔R, E=E)

Esto garantiza simetría L/R perfecta en el dataset y elimina cualquier sesgo de pie de inicio que pueda existir en los datos.

El modelo es igualmente preciso usando ground truth o sus propias predicciones como prev_limb. Esto indica que ha aprendido una representación interna auto-consistente de las secuencias — no depende de oracle information en absoluto.

1
Scheduled Sampling causa el salto de +3.3pp en época 5
La primera época con scheduled sampling (ss_prob=0.014) coincide exactamente con el mayor jump de accuracy en toda la training run: +3.3pp (de 82.0% a 85.3%). Esto sugiere que incluso un pequeño porcentaje de samples usando las predicciones propias del modelo tiene un efecto regularizador masivo — el modelo aprende a ser robusto a sus propios errores de predicción.
2
v8 supera el techo de v7b (30 épocas) en solo 9 épocas
v7b tardó 30 épocas (~53 min) en alcanzar su mejor resultado de 88.6%. v8 lo iguala en 9 épocas. La combinación de modelo más grande + scheduled sampling no solo produce mejor accuracy final — produce una curva de aprendizaje fundamentalmente más rápida.
3
Bug crítico: IndexError en MLX con forward pass fuera del compiled step
Hacer model() fuera del step compilado causa IndexError: unordered_map::at en MLX. El scheduled sampling interno requiere hacer un forward pass adicional para obtener las predicciones del modelo antes del training pass. La solución: implementar todo el scheduled sampling como un step_ss compilado con mx.compile que hace 2 forward passes internamente. El compile boundary es crítico — MLX necesita ver todo el grafo completo.
4
Bug previo (v7a): atención bidireccional con teacher-forcing = data leakage
v7a usaba atención bidireccional (sin causal mask) con teacher-forcing del prev_limb. Esto creaba leakage: el token i podía atender al token i+1, cuya feature prev_limb revelaba el label del token i. La validación con teacher-forcing parecía alta, pero la inferencia autorregresiva era mucho peor (AR gap grande). La causal mask en v7b+ corrigió esto completamente.
5
Both-mirror augmentation elimina sesgo de pie de inicio
Los charts de PIU tienen distribuciones asimétricas de L/R dependiendo del pie de inicio del stepper. Al incluir la versión espejada de cada chart en cada época, el dataset se balancea artificialmente: cada chart contribuye exactamente una versión L-start y una R-start. Esto previene que el modelo aprenda atajos basados en patrones globales de distribución de pies.
6
Escalado de modelo: 5M → 14.7M params (+2.9×) worth it
El incremento de d_model 256→384 y layers 6→8 triplica los parámetros pero solo aumenta el training time modestamente en hardware Apple Silicon (MLX). El ratio accuracy/costo es claramente positivo. El modelo más grande converge más rápido y a un mejor mínimo, sugiriendo que el modelo anterior era capacity-limited.
7
Warmup de 3 épocas es esencial para el scheduled sampling
Las primeras 3 épocas de v8 usan ss_prob=0 (solo teacher-forcing) para establecer una baseline de predicciones razonables antes de introducir el ruido de scheduled sampling. Sin warmup, el modelo recibiría predicciones caóticas como contexto prev_limb desde el inicio, haciendo el entrenamiento inestable. El salto en época 5 (primera con SS) confirma que el warmup fue suficiente para preparar el modelo.

Scheduled Sampling — ¿Cómo Funciona?

Training (ss_prob=0)
Para cada arrow i, prev_limb[i] = ground truth label del arrow i-1. El modelo siempre recibe contexto perfecto. Aprende bien pero sufre "exposure bias" — no sabe manejar sus propios errores.
→
Scheduled Sampling (0 < ss_prob < 1)
2 forward passes: primero predecir con teacher-forcing, luego reemplazar cada prev_limb[i] con predicción propia con prob ss_prob. El segundo pass calcula el loss. El modelo aprende a ser robusto a errores propios.
→
Inference (ss_prob=1 implícito)
Autoregressive: prev_limb[i] = predicción del modelo para el arrow i-1. Sin ground truth disponible. AR gap = 0.0pp indica que el modelo domina este modo completamente.
# Implementación crítica: DEBE estar dentro de mx.compile def step_ss(model, x, y, ss_prob, optimizer): # Pass 1: forward teacher-forced para obtener predicciones logits_tf = model(x) # x ya tiene oracle prev_limb preds = mx.argmax(logits_tf, axis=-1) # [N, T] # Reemplazar prev_limb con predicciones según ss_prob mask = mx.random.uniform(preds.shape) < ss_prob x_ss = replace_prev_limb(x, preds, mask) # prev_limb = pred donde mask=True # Pass 2: forward con x_ss, calcular loss real def loss_fn(model): logits = model(x_ss) return cross_entropy(logits, y).mean() loss, grads = mx.value_and_grad(loss_fn)(model) optimizer.update(model, grads) return loss step_ss_compiled = mx.compile(step_ss, inputs=model.state)
